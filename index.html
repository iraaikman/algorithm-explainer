01 / START WITH SOMETHING FAMILIAR

How algorithms
work.

Behind the complicated word is a simple idea:
a clear way to get from a question to an answer.

AN EVERYDAY ALGORITHM

Make a cup of tea.

Water + tea INPUT → Boil → steep 3 min → pour STEPS → A cup of tea OUTPUT

An algorithm is a finite list of unambiguous steps that turns an input into an output . “Finite” means it ends. “Unambiguous” means each step has one clear meaning.

EXPERIMENT 01

Find the largest number.

YOU CONTROL THE PACE

Read one number at a time. Remember the largest you’ve seen.

INPUT / FIVE NUMBERS
LARGEST SO FAR —
  1. Start with no largest number.
  2. Look at the next number.
  3. If it is bigger, remember it.
  4. When none remain, output the largest.

02 / THE INGREDIENTS OF LOGIC

Four building blocks.
Endless possibilities.

Order the work. Choose a path. Repeat. Remember.
These four ideas are enough to build surprisingly complex things.

↳

A variable is a named place to remember a value. “Count = 2” means the memory named count holds 2. It can change as the algorithm runs.

THE INSTRUCTIONS / PSEUDOCODE
Comparisons 0 Swaps 0 Writes 0

Ready.

A comparison asks how two values relate. A swap exchanges two values; a write puts one value in a position. Insertion and merge sort use writes rather than swaps.

04 / LESS WORK, SAME ANSWER

How much work
is enough?

First, the answer must be right and the steps must finish.
Then ask: what happens when the problem gets bigger?

The same input. Different effort.

At each size, all three sorts get exactly the same list. This chart counts comparisons of values, not elapsed time.

Big-O: a language for growth.

Big-O tells us how the work grows as the input grows. Read “O(n)” as “work that grows in proportion to the number of items.” Here, n simply means the number of items.

↳

These are growth patterns, not exact stopwatch predictions. The counts above describe particular inputs; the patterns below describe worst-case growth. Memory, clarity, and the kind of input matter too. Binary search is fast, but sorting an unsorted list first also costs work.
